# 今日训练草稿保存设计

## 目标

当用户要求 945 生成今天的训练时，Agent 返回可查看的今日训练草稿。用户只需点击一次“确认保存”，系统即将该草稿保存为今天的训练安排；不会把确认动作重新发送给模型，也不会出现第二次确认。

保存后，“今日”看板的“今日训练”区域必须显示刚保存的训练名称、时长和动作安排。刷新页面后，该安排仍存在。

## 范围与边界

- 只替换当前日期的训练内容。
- 后续日期的训练、饮食计划和训练历史记录不变。
- 保存通过创建新的 active 计划版本完成：旧 active 计划归档，新版本仅替换今天的 `WorkoutPlanDay`。
- Agent、模型或草稿本身不能直接写入计划。
- 用户取消草稿时不写入任何数据。
- 沿用现有视觉系统；只增加训练草稿的内容展示和一个“确认保存”操作。

## 数据与接口

### 草稿

`RecordDraft.type` 新增 `today_workout_plan`。草稿载荷使用完整的 `WorkoutPlanDay`：

- `date`
- `name`
- `focus`
- `duration_minutes`
- `exercises[]`，每项包含动作 ID、名称、目标肌群、组数、次数、目标重量、休息和备注

后端仅接受目标日期等于应用当前日期、内容完整且通过模型约束校验的草稿。

### 保存接口

新增 `POST /api/plans/{plan_id}/replace-today-workout`。

请求包含 `user_id`、`confirmed: true` 和完整 `workout_day`。接口必须：

1. 校验调用用户拥有该 active 计划。
2. 校验 `workout_day.date` 是当前日期。
3. 复制 active 计划并只替换同日期训练日。
4. 归档旧 active 计划，保存复制后的新 active 计划。
5. 返回新 active 计划。

## 交互流程

1. 用户询问今天训练，或明确要求生成今天训练。
2. Agent 返回训练说明和 `today_workout_plan` 草稿。
3. Agent 页面在草稿预览下方展示唯一的“确认保存”按钮。
4. 点击按钮后，前端仅调用保存接口；不调用 `/api/agent/chat`。
5. 成功后移除草稿、刷新 `PlanContext` 和今日数据，并显示保存结果。
6. Today 页面从当前 active 计划读取今天训练，显示训练名称、时长和动作；没有计划或没有当日训练才显示空态。

## 失败与安全处理

- 无 active 计划、日期不匹配、草稿字段不完整或保存接口失败时，不改变现有计划。
- 高风险身体信号不生成训练草稿。
- 同一次草稿保存期间，确认按钮禁用，避免重复写入。
- 页面刷新后不允许把文字“确认保存”当作新的聊天输入或触发模型调用。

## 验收标准

1. 生成草稿前，当前计划与今日看板不变。
2. 草稿预览只有一个“确认保存”操作。
3. 点击一次后只发出一次 `replace-today-workout` 请求，且不发出新的 Agent 聊天请求。
4. 返回的新 active 计划只改变今天训练，后续日期不变，旧计划为 archived。
5. 保存成功后 Today 看板立即显示新训练；刷新后仍显示。
6. 取消、无计划、非法草稿、高风险输入和失败响应均不写入计划。
