## 3. 主要发现

### 3.1 移动端顶部导航被压缩

证据：`08-mobile-today.png`、`09-mobile-diet.png`、`10-mobile-agent.png`

移动端顶部仍保留一排图标式侧栏入口，部分图标在顶部区域被截断，只能看到一部分。虽然没有检测到页面级水平溢出，但视觉上像是桌面 rail 被硬塞到移动端。

影响：

- 首屏上方出现不完整控件，降低完成度感。
- 图标按钮的可点击目标和语义不够明确。
- 和 PRD 的“移动端核心流程可用、没有明显元素重叠”存在风险。

建议：

- 移动端隐藏桌面 rail，改为底部 4 到 5 项主导航，或顶部单行横向导航。
- 移动端只保留核心入口：今日、训练、饮食、Agent、设置。
- 图标按钮增加稳定尺寸和可访问名称，不要露出被裁切的 hover/复制图层。

### 3.2 饮食移动端日期栏占用过多首屏空间

证据：`09-mobile-diet.png`

饮食页移动端的周日期选择从横排变成竖排大卡片，`Mon 16` 到 `Sun 22` 占据大量首屏高度，导致营养目标和计划餐被推到下方。

影响：

- 用户进入饮食页时，最想看的计划餐和记录入口不够靠前。
- 这会削弱 MVP 中“计划餐确认和手动输入”的核心任务效率。

建议：

- 日期选择器在移动端改为横向可滚动 pill row。
- 默认只显示 5 到 7 个短按钮，不使用大块纵向布局。
- 把“今日营养目标”和“计划餐”提升到首屏内。

### 3.3 Agent 页面缺少明确页面标题

证据：`06-desktop-agent.png`、`10-mobile-agent.png`

自动截图结果中 `/agent` 的 `h1` 为空。视觉上用户能理解这里是聊天页，但页面结构没有明确一级标题。

影响：

- 截图审查、屏幕阅读器和自动化语义判断都难以识别页面身份。
- 和其他页面的结构不一致。

建议：

- Agent 页面加入视觉上低干扰但语义明确的 `h1`，例如“Agent”或“945 智能教练”。
- 如果不想破坏视觉，可使用现有卡片顶部标题作为 `h1`，而不是单独增加大标题。

### 3.4 训练页偏离 PRD 中“训练计划中心”的职责

证据：`02-desktop-workout.png`

当前训练页像单次训练执行页：有动作、组数、重量、完成状态和完成训练按钮。但 PRD 对训练页的要求还包括本周训练计划、每天安排、训练历史、完成率和训练量趋势。

影响：

- 作为 demo 可演示训练执行，但不够支撑“训练页”长期信息架构。
- 用户难以从这里看完整一周安排和历史趋势。

建议：

- 保留当前训练执行卡作为主模块。
- 追加本周计划列表、最近训练记录、训练完成率和训练量摘要。
- 如果视觉空间有限，桌面端用右侧栏，移动端用分段 Tabs。

### 3.5 设置页部分控件缺少真实状态边界

证据：`07-desktop-settings.png`

训练目标按钮、通知开关、教练语气选项看起来可操作，但目前没有从截图或测试证据看到明确保存反馈。数据导出按钮已标注“后续能力”，这个边界是清楚的。

影响：

- 用户可能以为目标和开关已经可持久保存。
- 后续接真实后端时容易混淆 demo 控件和真实设置。

建议：

- 可操作控件点击后显示 notice。
- 未完成能力直接禁用或标注“后续能力”。
- 设置页拆成“已可用”和“即将支持”两组。

### 3.6 部分主产品文案仍是组件内条件文案

证据：`src/pages/DietPage.tsx`、`src/pages/AgentPage.tsx`、`src/pages/AdvicePage.tsx`

当前已经有 i18n 结构，但一些高保真 UI 文案仍通过 `isChinese ? ... : ...` 写在组件内。它不会导致构建失败，但和 PRD 中“前端所有用户可见文案不得硬编码在组件中”的目标不完全一致。

影响：

- 后续扩展语言时维护成本上升。
- 页面组件会继续混合业务结构和文案资源。

建议：

- 下一轮把高保真新增文案补进 `src/i18n/*`。
- demo 数据中的建议正文可以暂时保留，但导航、按钮、标题、标签、提示语应全部走 i18n key。

## 4. 当前不阻塞的问题

- 桌面端没有明显水平溢出。
- 当前 4 个自动化测试全部通过。
- 主要记录动作都有反馈：训练状态、计划餐确认、手动餐食、身体数据、Agent 草稿确认、建议采纳。
- Stitch reference 仍可保留在 `/prototype/*`，不影响主产品路由。

## 5. 建议的下一步

### P0：移动端导航和饮食页首屏修复

目标：解决最明显的移动端视觉问题。

任务：

1. 移动端隐藏被截断的左侧 rail 图标。
2. 增加稳定的移动端主导航。
3. 饮食页日期选择器改为横向滚动 pill row。
4. 重新截图 `/`、`/diet`、`/agent` 的移动端状态。

验收：

- 移动端顶部没有被裁切图标。
- 饮食页首屏能看到营养目标和至少一部分计划餐。
- `npm run qa:app` 通过。

### P1：Agent 页面语义和训练页信息架构补齐

目标：让页面职责更贴近 PRD。

任务：

1. Agent 页面增加明确 `h1`。
2. 训练页补本周计划、训练历史和完成率摘要。
3. 设置页把未完成控件禁用或增加状态反馈。

验收：

- `/agent` 自动读取到明确页面标题。
- `/workout` 不只是一张训练执行页。
- 设置页 demo/后续能力边界清楚。

### P2：i18n 收口

目标：让主产品文案结构更干净。

任务：

1. 扫描 `src/pages` 内的 `isChinese ?` 用户可见文案。
2. 把导航、按钮、标签、提示、卡片标题移动到 i18n 词典。
3. 保留 demo 数据内容作为 mock data，不强行迁移。

验收：

- 主产品组件内不再新增大段中英文条件文案。
- 中英文切换后页面结构和按钮文案一致。

## 6. 审查边界

本次是截图驱动的视觉与 UX QA，不等同于完整 WCAG 审计。以下内容仍需要单独验证：

- 键盘完整可达性。
- 屏幕阅读器朗读顺序。
- 颜色对比精确数值。
- 真实后端数据接入后的加载、错误和空状态。
- 长文本、极端数值和多语言扩展后的布局稳定性。
